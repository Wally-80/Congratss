# 🏛️ ARCHITECTURE DECISION RECORDS (ADR)

This document formalizes core technological choices mapping the constraints, context, and subsequent technical implications of foundational platform decisions.

---

### ADR-001: Adopting Next.js App Router
- **Context**: The platform required a seamless blend of Server Side Rendering (SSR) for heavily optimized SEO paths, and complex client-side interactivity for the celebration dashboards.
- **Decision**: Next.js 15 (App Router) was implemented as the core front-end routing interface.
- **Implication**: Ensures excellent time-to-first-byte while reducing initial chunk payloads. Standardized data fetching methods rely strictly on native `fetch` extensions rather than legacy patterns.

### ADR-002: Leveraging Firebase as Backend-as-a-Service
- **Context**: Data schemas required immense horizontal flexibility given the variation in specific event typologies, combined with extreme low-configuration user authentication.
- **Decision**: Adopt Firebase Auth, Firestore, and Storage native JS SDKs.
- **Implication**: Trades complex relational referential integrity (SQL) for extreme scalability and real-time pub/sub synchronization natively inside the client dashboard. Access control is managed explicitly via centralized Firestore Rules.

### ADR-003: Tailwind CSS for Design Systems
- **Context**: Rapid iteration cycles demand heavily constrained design tokens devoid of specificity wars generated by cascading generic CSS sheets.
- **Decision**: Implement Tailwind CSS V4 for unified utility-first styling patterns.
- **Implication**: Allows direct-component collocation of view styles guaranteeing minimal dead-code CSS shipping to production bundles while maintaining responsive design paradigms natively.

### ADR-004: Capacitor native Wrappers over React Native
- **Context**: Dual-maintenance between a web-app codebase and a mobile-specific codebase (React Native/Swift/Kotlin) creates extreme overhead for early lifecycle platforms.
- **Decision**: Implement Ionic Capacitor as the core native compilation bridging tool.
- **Implication**: Single codebase architecture guarantees web feature parity with native application releases simultaneously, maximizing developer velocity while retaining native system-level API access (Notifications, File System).
